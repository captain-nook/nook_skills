# 验收标准

改完代码或词表后，按这几条验收。能用命令检查的都写了命令。

## 1 自动检查（必须全过）

```
python xhs.py selftest
```

覆盖：品牌未设置时拒绝执行；每个页型有渲染函数；素材库文件都在、id 不重复；四套主题对比度达标；所有示例方案和 12 个框架方案通过校验；错误方案被拦下；三套风格各出一份图且没有版面问题（文字溢出、留白不足、贴纸压住文字）；示例正文包通过、错误正文包被拦；skill 目录里没有本机路径和个人信息；字体许可文件在位。

## 2 一次完整交付（agent 能独立做完）

用一份真实素材，按 nook-xhswrite 的关卡 0 到 5 走一遍，满足：

1. 第一次运行时被品牌设置拦住，问了用户四件事，设置后不再问。
2. 每个关卡都停下等用户，没有自己往下走；没有自己找图。
3. `deliver` 一次性通过（或按报错改到通过）：方案校验、正文检查、出图。
4. 封面加第 2 页读者能看出这是讲什么、给谁、得到什么。
5. 图上的数字都能在 `meta.facts` 里找到；没有数据的页标“推理，无数据”。
6. 贴纸按七步判断放，有贴纸的页不超过 60%，没有压住文字。
7. 逐页看过图，没有文字被截断、没有重叠。

## 3 回归素材

仓库里 `回归测试/`（不随 skill 发布）有三份素材，各代表一类，改动后重跑 `deliver`：长逐字稿（约 1 万字）、短帖（不到 100 字）、一句话念头。三份都要通过。薄素材走“篇幅：短”，不用空话凑字数。

## 4 换 agent 试跑（人工）

在要支持的 agent 上，只给它 SKILL.md 的路径和一份素材，看它能否：读到并执行关卡 0，遇到报错能照着改，到 `deliver` 通过。卡在哪一步，就把那一步的说明写得更具体。这一项需要在对应的 agent 里手动做，selftest 不覆盖。
