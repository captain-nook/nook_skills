# 关卡输出模板

五个关卡每关输出一份固定格式的文件或表，弱模型照着填。文件放在方案文件旁边（同一个文件夹），不要散落到别处。

## 关卡 1：事实清单（facts.md）

```
# 素材类型
文章 / 逐字稿 / 新闻 / 一句话念头（四选一）

# 事实清单
| 编号 | 事实（只写素材里有的，数字带单位） | 原文位置 |
|---|---|---|
| f1 | …… | 第 3 段 |
| f2 | …… | 00:12:30 |

# 一句话核心
给【谁】，获得【什么】。

# 主题词
词1、词2（1 到 4 个，要写进封面或第 2 页）

# 风险
素材里没有数据 / 素材只有观点 / 其他（没有就写“无”）
```

事实清单里的编号和文字之后原样写进方案 JSON 的 `meta.facts`，图上出现的数字都要能在里面找到。素材只有一句话时，事实清单可以只有 1 到 2 条，其余页是推理出的结构，提纲里标“推理，无数据”。

## 关卡 2：逐页提纲（outline.md）

```
# 框架
选哪个框架，一句话理由。

# 风格
默认风格是什么；这篇用哪套（paper / dark / ticket），一句话理由。

# 提纲
| 页 | 页型 | 这一页的一句话 | 事实来源 | 视觉元素 |
|---|---|---|---|---|
| 1 | cover_quote | …… | f1 | 放：magic_wand |
| 2 | idea | …… | 推理，无数据 | 不放：页面已满 |

# 检查
- 封面加第 2 页，回答了“这是什么、给谁、得到什么”：是 / 否
- 相邻两页页型不同，至少 3 种页型：是 / 否
```

## 关卡 3：素材需求清单（needs.md）

```
| 页 | 页型 | 需要什么 | 为什么 | 格式 |
|---|---|---|---|---|
| 3 | step | 工具界面截图 | 这一页讲操作 | PNG，宽度不少于 1000 |

没有需要就写：无。
停下，等用户把文件放进 inputs/，或说明这页换成不用图的页型。
```

## 关卡 4：封面候选（covers.md）

```
| 候选 | 页型 | 封面字 | 钩子类型 | 风格 |
|---|---|---|---|---|
| A | cover_list | …… | 数字清单 | paper |
| B | cover_person | …… | 结果承诺 | paper |
```

钩子类型从 `hooks.md` 里选，封面字要短，缩到手机缩略图大小还读得清。

## 关卡 5：方案和正文包

方案是 `plan.json`（结构见 nook-xhspage 的 `references/schema.md`，示例见 `references/plans/`）。正文包是 `post.md`，五节固定，缺一节 `check-post` 就报错：

```
## 标题
- 搜索型：（15 到 25 字，含工具名和场景）
- 结果型：（15 到 25 字，亮出结果）
- 清单型：（15 到 25 字，带数量）

## 标签
#关键词1 #关键词2 #关键词3 #关键词4 #关键词5

## 正文
（400 到 800 字，自然段，第三人称，第一句直接说内容，不用粗体和列表。素材只有一两条事实时，第一行写“篇幅：短（素材只有 N 条事实）”，下限放宽到 100 字，不要用空话凑字数）

## 删除测试记录
已调用 nook-alive 做删除测试。删除了：……（或：无命中）。

## 事实对照
正文里的数字和名称对应事实清单：f1、f2……
```

交付命令：`python xhs.py deliver plan.json post.md`，方案校验、正文检查、出图三项都过才算完成。
