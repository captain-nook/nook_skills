# 内容框架库

素材的结构是什么，就用什么框架，不是所有内容都排成一列清单。写法参照 nook-ppt 的图示表：先判断内容的结构，再选框架，框架决定页序和页型。12 个框架，覆盖绝大多数素材。一篇图文只选一个主框架，必要时在其中一页嵌入另一个（例如主框架是“问题、原因、做法”，做法那一页用步骤）。

框架里的位置是推理出来的结构，数字、事实、引语只能来自素材。素材里没有数据，就不放数据，不编。

## 1 选框架：看素材长什么样

| 素材的结构 | 框架 |
|---|---|
| 有先后顺序的操作 | 1 步骤流程 |
| 同类的几样东西 | 2 并列清单 |
| 改变前后的差别 | 3 前后对比 |
| 一个麻烦，有原因，有解法 | 4 问题、原因、做法 |
| 要讲清一个概念或方法 | 5 是什么、为什么、怎么做 |
| 有上下层、基础和上层 | 6 层级体系 |
| 首尾相接、越做越好 | 7 循环迭代 |
| 一层层筛选、转化、流失 | 8 筛选漏斗 |
| 要在几件事里排优先级 | 9 取舍矩阵 |
| 数据随时间或在几项之间变化 | 10 数据变化 |
| 有一条可以直接使用的指令或模板 | 11 指令模板 |
| 常见错误和正确做法 | 12 误区对照 |
| 只有一个判断，没有展开 | 5（是什么、为什么、怎么做）补成 3 个点 |

素材只有一句话时，用 5 或 4 拆成 3 个点，每个点是推理出来的结构，不放数据。

## 2 框架清单

字段说明：用意是读者看完这一页明白什么；页序是建议顺序，括号里是页型 id（见 nook-xhspage 的 `list-types`）；封面是适合的封面页型。

### 1 步骤流程
- 适合：操作教程、工作流搭建、一次完整的做法。
- 用意：读者照着做得出结果。
- 页序：封面 → 目录（toc）→ 每步一页（step，有截图；没有截图用 list 或 idea）→ 成果（result）→ 收尾（closing）。步骤超过 5 步，合并成 5 步以内，细节放正文。
- 封面：cover_list（“N 步做 XX”）。

### 2 并列清单
- 适合：N 个工具、N 条方法、N 个检查项。
- 用意：读者一次看到全部，并能挑一个先用。
- 页序：封面 → 清单总览（list，3 到 5 项）→ 重点项展开（step、prompt、idea，只展开最关键的 1 到 3 项）→ 收尾。
- 封面：cover_list。

### 3 前后对比
- 适合：工具或方法带来的改变、新旧做法、A 对 B。
- 用意：差别一眼可见。
- 页序：封面 → 对比（compare）→ 差别的原因或数据（bar、idea）→ 做法（step）→ 收尾。
- 封面：cover_person（结果承诺）。

### 4 问题、原因、做法
- 适合：痛点解决、避坑、经验复盘。
- 用意：读者认出自己的问题，并知道怎么办。
- 页序：封面（点出问题）→ 问题是什么（idea 或 quote）→ 原因（list，2 到 3 条，或 pyramid）→ 做法（step 或 prompt）→ 结果（result 或 compare）→ 收尾。
- 封面：cover_quote 或 cover_person。

### 5 是什么、为什么、怎么做
- 适合：概念解释、方法介绍；也用于只有一句话的素材。
- 用意：读者弄懂一件事并会用一次。
- 页序：封面 → 是什么（idea）→ 为什么（list 或 pyramid）→ 怎么做（step、prompt、cycle）→ 收尾。
- 封面：cover_quote。

### 6 层级体系
- 适合：体系、分层、基础与上层（技能树、产品结构）。
- 用意：读者看清结构和先后。
- 页序：封面 → 全貌（pyramid）→ 每一层一页（list 或 idea，只展开最关键的 2 层）→ 收尾。
- 封面：cover_person 或 cover_quote。

### 7 循环迭代
- 适合：反复进行的流程、复盘、飞轮。
- 用意：读者明白为什么越做越好。
- 页序：封面 → 循环（cycle）→ 每个环节一句话（list）→ 数据（line 或 bar，有就放）→ 收尾。
- 封面：cover_person。

### 8 筛选漏斗
- 适合：选题筛选、转化、一层层淘汰。
- 用意：读者看到数量怎么变少、标准是什么。
- 页序：封面 → 漏斗（funnel）→ 每层的标准（list）→ 留下来的结果（result 或 idea）→ 收尾。
- 封面：cover_list 或 cover_quote。

### 9 取舍矩阵
- 适合：优先级、选型、几件事先做哪个。
- 用意：读者得到一个先后判断。
- 页序：封面 → 矩阵（matrix）→ 先做的那一项展开（step 或 list）→ 其余各一句话（list）→ 收尾。
- 封面：cover_person。

### 10 数据变化
- 适合：增长、耗时变化、几项数据对比；必须有真实数据。
- 用意：数据说明变化。
- 页序：封面 → 数据图（line 或 bar）→ 变化的原因（list 或 pyramid）→ 做法（step）→ 收尾。
- 封面：cover_person 或 cover_list。
- 没有数据就不用这个框架。

### 11 指令模板
- 适合：提示词、脚本、配置、模板，读者要复制。
- 用意：读者复制就能用。
- 页序：封面 → 使用场景（idea）→ 指令（prompt）→ 怎么改成自己的（list，2 到 3 条）→ 效果（compare 或 result）→ 收尾。
- 封面：cover_quote 或 cover_list。
- 指令原文必须来自素材或用户，不由 agent 编造。

### 12 误区对照
- 适合：常见错误、避坑、纠偏。
- 用意：读者对照自己，避开错误。
- 页序：封面 → 误区总览（list）→ 错和对（compare，每页一对，最多 2 对）→ 判断标准（idea）→ 收尾。
- 封面：cover_quote 或 cover_list。

## 3 示例方案

每个框架有一份可以通过校验的方案，在 `plans/` 里，文件名前两位是框架编号：01 步骤流程、02 并列清单、03 前后对比、04 问题原因做法、05 是什么为什么怎么做、06 层级体系、07 循环迭代、08 筛选漏斗、09 取舍矩阵、10 数据变化、11 指令模板、12 误区对照。照着改主题词、页文字和事实清单即可。时间轴、大数字、多截图三种新页型的用法见 nook-xhspage 的 `examples/demo_new_types.json`。

## 4 通用规则

1. 3 到 9 页，页数由框架决定，一页一个点。素材再少也凑够 3 个点，但每个点要有不同的信息，不用同义句填页。
2. 图上放标题、框架、事实、数据、流程和逻辑。展开的论述、背景、体会写进正文，不画进图里。
3. 每页文字写到“删掉任何一个词都会少信息”为止。版面能放下多少是上限，不是目标；几个字说清的就用几个字。
4. 相邻两页不用同一页型，一篇至少用 3 种页型。
5. 页型按内容的结构选，没有对应页型时用 list、step 或 idea 代替，不硬凑图示。
6. 需要截图或成果图的页（step、result），先向用户要，不自己找、不用占位。
7. 最后一页用 closing 或 back_cover；back_cover 只放名字和一句话。
