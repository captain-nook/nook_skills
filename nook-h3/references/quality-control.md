# H3 视频输出质检与返工

本规范用于 `nook-h3` 的单条任务和长时间批处理。ComfyUI 返回 `success`、生成了文件，只代表推理完成，不代表镜头合格。

## 处理顺序

1. 每次提交都记录镜头 ID、工作流、提示词、参考物料、时长、分辨率、精度、随机种子、prompt_id 和实际输出文件。
2. 输出后先做技术质检，再做内容质检。
3. 两类质检都通过，才把镜头标记为 `completed`。
4. 明显失败时记录具体失败项，使用新种子重跑同一镜头，并只针对失败项增强提示词；不要无依据重写整个提示词。
5. 单镜头达到首轮重试上限仍失败时，标记为 `rework_pending`，继续生成后续镜头。首轮队列完成后，再处理返工队列，避免一条难镜头阻塞整批任务。
6. 返工仍无法通过时标记为 `manual_review`，保留全部尝试和输出，不把失败成片冒充成最终素材。

## 技术质检

- 文件存在且可以读取。
- 视频时长与任务时长基本一致，不是零时长或异常截断。
- 画幅为 16:9，分辨率符合工作流设置。
- 视频流可解码，不是全黑、严重冻结或损坏文件。
- 需要现场声音或台词的镜头包含可用音轨；音轨不是全程静音。
- 输出文件确实属于当前 prompt_id，不能误取上一条任务的文件。

## 内容质检

必须结合该镜头的分镜卡、提示词和参考物料逐项检查：

- **主体**：人物、动作、朝向、构图和景别符合分镜；没有多手、多脚、肢体粘连、严重脸崩或凭空出现的主体。
- **开场构图**：分镜要求开场可见的主体，必须从第一帧就按要求完整、清晰地处在画面中。若主体从画外迟入、直到素材末段才完整出现，导致有效动作和可剪辑余量不足，判为失败。只有分镜明确要求“画外入场”时才允许这样生成。
- **人物参考**：需要女主一致性的镜头，人物外观与本次明确提交的女主多视角参考相符。
- **场景参考**：场景、摊位、奶茶店等与本次明确提交的场景参考相符，没有不应出现的人物或物体。
- **镜头运动**：必须看得到分镜要求的跟随、推进、拉远、环绕、横移等运动；跟随镜头具有克制但可感知的手持横向微摆、垂直呼吸起伏，步行时有同步步幅起伏。固定机位或只有主体动、镜头不动，判为失败。
- **仙界环境运动**：远景云海保持高度和整体轮廓稳定，仅有低幅度、低速的层内横向流动与细微纹理迁移；中远景云层有细微可见的方向位移，建筑可见度基本不变。完全静止判为失败；出现海浪式大起大落、成片云墙向镜头逼近、云层快速增厚并遮挡建筑，也判为失败。
- **台词**：只有分镜明确要求台词时才检查口型和语音。中文必须逐字可辨、与台词一致、口型基本同步；乱码、外语感、缺词、改词、女主不张嘴或没有声音均判失败。
  可先用 `scripts/check_h3_dialogue.ps1` 对 `prepare_h3_qc.py` 导出的 `audio.wav` 做离线识别证据。准确匹配且置信度达标可辅助通过；低置信度、乱码或不匹配不能放行，仍需语义复核或重跑。
- **现场声音**：除 BGM 外，风声、脚步、衣料、云海低频、鸟鸣、仙鹤鸣、集市喧闹、摊位声等按画面逻辑出现。热闹场景完全无环境声、行走却无脚步、需要台词却无台词，判为失败。
- **音乐**：项目要求无 BGM 时，不得出现配乐；现场环境声不属于 BGM。
- **连续性**：首尾帧任务应正确衔接两张物料；相邻分镜的方向、位置和动作应便于后期剪辑。

## 重跑策略

每次重跑必须换随机种子。根据失败项做最小修订：

- 台词失败：保留官方 H3 对话标签，把 `<Subject N> (Sx)` 直接放在实际发声句上；强化语言、原文、自然口型和发声时间段。台词期间把人声置于前景并压低竞争性环境声，台词结束后再引入脚步、鸟鸣、风铃或集市层；不要添加第二套台词写法。
- 镜头过稳：把可见的手持横摆、垂直呼吸起伏、步幅起伏写进镜头运动，并给出相对幅度或连续性要求。
- 云海不动：强调远景云海保持稳定高度与轮廓，仅增加低幅度、低速的层内平移和细微纹理流动；中远景云层缓慢横移，不能向镜头推进或扩大遮挡建筑。
- 云海海浪化：删除 `surge`、`roll`、`wave motion`、`broad coherent waves/layers`、`billow toward camera` 及同义高能词。改写为“稳定高度、稳定外轮廓、细纹理低速沿地平线方向迁移”，并要求宫殿轮廓持续可读。不要同时保留旧的高能运动描述。
- 主体迟入画：先核对工作流。I2VA/FL2VA 应重做首帧，使主体在首帧即符合开场构图；Ref2VA 应写明主体从第一帧已完整入画、占画比例和位置，不用“enters from the side/off-screen”等措辞消耗素材时长。
- 音效缺失：在 `overall_soundscape` 写清该镜头实际需要的现场声及其前后层次；保持 `non_diegetic_music: N/A`。
- 肢体错误：简化同一时刻的肢体动作，保持景别和叙事目的，不通过添加大量负面词污染提示词。
- 参考漂移：核对工作流类型与真正送入 H3 的参考物料，不用文字替代漏送的参考图。

## 状态字段

推荐状态：

- `queued`：待提交
- `running`：ComfyUI 正在执行
- `technical_qc`：技术质检
- `content_qc`：内容质检
- `completed`：两类质检均通过
- `retry_pending`：本轮立即重跑
- `rework_pending`：移到首轮队列末尾后返工
- `manual_review`：自动返工后仍需人工判断
- `submit_failed`：提交或推理失败

每次尝试至少记录：`attempt`、`seed`、`prompt_id`、`output`、`technical_qc`、`content_qc`、`failure_reasons`、`prompt_revision` 和时间戳。

可用以下命令生成技术报告和接触表；再结合分镜逐项做人工语义质检：

```powershell
python .\scripts\prepare_h3_qc.py '.\output\clip.mp4' `
  --shot-id 'clip-001' --expected-duration 4 `
  --output-dir '.\qc\clip-001'
```
