# 04 结果清洗（环 4）

## 4.1 这一环解决什么问题

AnySearch 默认返回的是结构化 JSON（或原始 Markdown）。但**直接给用户看不行**：
- 字段名是英文（author / likes / published_at）
- 时间戳是 ISO 格式（2026-07-13T15:21:57+00:00）
- License 字段是字符串（"CC BY 4.0"），没有"能不能商用"的判断
- 跨平台对比时，字段不统一（X 有 retweets，微博只有转发）
- 没有目录、没有标题、没有抓取时间、没有元信息

**环 4 = 把脏 JSON 翻译成干净的、统一的、可读的 Markdown。**

## 4.2 核心 Schema

```yaml
cleaning:
  input_format: json | markdown   # AnySearch 默认输出
  template: <模板名>             # 选哪个 Markdown 模板
  fields:                        # 字段映射
    - source: author             # AnySearch 字段
      target: 作者               # 输出字段
      required: true             # 缺失是否阻断
    - source: published_at
      target: 发布时间
      formatter: iso_to_zh       # 2026-07-13T15:21:57+00:00 → 2026-07-13 15:21 (UTC+0)
    - source: likes
      target: 点赞
      formatter: int_with_comma  # 1234 → 1,234
    - source: text
      target: 正文
      formatter: truncate_200    # 截断到 200 字
  dedup:
    by: [url, author+text_hash]  # 去重键
  sort:
    by: score
    desc: true
  truncate:
    text: 200
  include_meta:                  # 顶部必带元信息
    - query
    - domain
    - sub_domain
    - fetched_at
    - anysearch_cost_ms
  license_handling:              # 配图场景专用
    cc0: green_tag               # 🟢 CC0 - 可商用
    cc_by: yellow_tag            # 🟡 CC BY - 需署名
    cc_by_nc: red_tag            # 🔴 CC BY-NC - 不可商用
    unsplash_license: green_tag
    pexels_license: green_tag
    unknown: red_tag             # 🔴 未知 - 不入商用库
```

## 4.3 清洗规则

### 4.3.1 字段映射必须有，缺失不允许静默丢

每条 AnySearch 字段 → 输出字段都要写映射。AnySearch 没返回的字段，输出标 `null`，不静默吞。

```markdown
❌ 反例：字段没映射 → 输出没这字段 → 用户以为没数据
✅ 正例：字段没映射 → 输出 "数据缺失：[字段名]" + 标 `null`
```

### 4.3.2 必带元信息五件套

每份清洗后的 Markdown 顶部必须有：

```markdown
---
query: AI Agent
domain: social_media
sub_domain: social_media.social_media (type=reddit_comment)
fetched_at: 2026-07-20 17:43:12 (UTC+8)
anysearch_cost_ms: 3210
source: AnySearch CLI v2.1.0
---
```

缺元信息 = 裸数据，不入知识库。

### 4.3.3 跨平台字段对齐

不同平台字段名不统一，Skill 内部维护 `field_normalizer.yaml`：

| 通用字段 | X | Reddit | 微博 | 知乎 | 微信公众号 |
|---|---|---|---|---|---|
| 互动 | likes | score | likes | vote | read_count |
| 转发 | retweets | - | reposts | - | - |
| 评论 | replies | comments | comments | comment_count | - |
| 收藏 | bookmarks | - | - | favorite | - |
| 浏览 | views | - | - | view_count | - |

**对齐原则**：取所有平台的并集，缺的平台该字段标 `-`。

### 4.3.4 时间格式统一

AnySearch 返回 ISO 格式（带时区）。Skill 默认转 `YYYY-MM-DD HH:MM (UTC+8)`，方便阅读。

```yaml
formatters:
  iso_to_zh:
    input: "2026-07-13T15:21:57+00:00"
    output: "2026-07-13 23:21 (UTC+8)"  # 假设东八区
```

### 4.3.5 AI 生成内容检测（ai_generated_detection）

AnySearch 抓回来的内容可能混入 AI 生成的低质文本（尤其公众号 / 知乎 / X 上的"AI 水文"）。Skill 在清洗阶段对每条结果做信号检测，命中阈值则打标但**不直接删除**（保留供人工判断）。

```yaml
ai_generated_detection:
  enabled: true                 # 默认开启
  signals:                      # 命中以下信号累计计分
    - excessive_lists           # 全文几乎全为列表/要点，缺叙事段落
    - generic_phrasing          # "在当今快速发展的..." / "随着 AI 不断进步..." 类套话开头
    - low_lexical_diversity     # 词汇多样性低（type-token ratio 低于阈值）
    - uniform_sentence_length   # 句长高度均匀（标准差 < 阈值）
    - missing_personal_voice    # 无第一人称视角 / 无具体经验 / 无具体数字
  scoring: weighted_sum         # 信号加权累计
  threshold: 0.4                # ≥0.4 判为疑似（260721 验证后从 0.7 调低，Reddit 真人讨论天然带个人视角，0.7 阈值无区分度）
  action: tag                   # tag / filter / quarantine（默认仅打标）
  tag_field: ai_suspected       # 输出字段名
  tag_value: true               # 命中时写入的值
```

**强制规则**：
- 命中 `ai_suspected: true` 的内容**不直接删除**，保留在结果中供人工判断。
- 商用文案 / 配图描述（公众号 / 小红书 / 抖音）**禁止**直接采用 `ai_suspected: true` 的正文。
- 若下游有"评论区痛点挖掘"类需求：`ai_suspected: true` 的内容**不计入**痛点信号（避免 AI 水文污染选题信号）。
- 与 `anonymity_risk`（见 `domain_map.yaml`）联动：高匿名平台 + `ai_suspected: true` 双重命中 → 可信度再降一档。
- 检测结果写入顶部元信息块：`ai_suspected_count: N` / `ai_suspected_rate: 0.X`，缺元信息按 4.3.2 同等视为裸数据。

### 4.3.6 License 三色标签（配图场景）

| License | 标签 | 是否可商用 | 是否需署名 |
|---|---|---|---|
| CC0 / Public Domain | 🟢 | ✅ | - |
| Unsplash License | 🟢 | ✅ | - |
| Pexels License | 🟢 | ✅ | - |
| CC BY 4.0 | 🟡 | ✅ | 必须署名 |
| CC BY-SA | 🟡 | ✅ | 必须署名 + 同协议开源 |
| CC BY-NC | 🔴 | ❌ | - |
| 未知 / License 字段缺失 | 🔴 | ❌ | - |

**强制规则**：商用图库（公众号 / 小红书 / 抖音）只能入库 🟢 图。🟡 / 🔴 必须标 `commercial_ok: false` 并提示用户。

### 4.3.7 去重策略

```yaml
dedup:
  primary_key: url                # 主键：URL
  secondary_key: author+text_hash # 副键：作者+正文 hash
  behavior: keep_first            # 保留第一次出现的
```

跨批次复现 = 持续热度信号，标 `seen_count: N`，高复现 = 高加权。

## 4.5 时间窗 skill 层过滤（呈现层核心）

AnySearch 的 social_media 域不支持时间参数（详见 [02_参数路由_领域映射.md § 2.4.5](02_参数路由_领域映射.md)），但用户经常要"72h/24h/本周"。本层在 skill 层实现时间窗过滤。

### 4.5.1 三层实现

| 层 | 触发条件 | 实现 | 失败处理 |
|---|---|---|---|
| ① 翻译层（环 1+2） | 识别到时间窗词 | 把时间词写进 query 自然语言（"AI news in the last 72 hours"） | 总能执行，但效果依赖后端排序引擎 |
| ② 参数层（环 2） | 话题和 finance/academic 相关 | 优先用带 period/year_from 参数的域 | 话题不相关时跳过此层 |
| ③ 呈现层（环 4） | 结果有 published_at 字段 | 按 published_at 硬过滤 | 字段缺失时标 `time_window_check: FAILED` |

### 4.5.2 呈现层过滤逻辑

```yaml
time_window_filter:
  detected: true                    # 来自环 1 翻译层识别
  original_phrase: "72 小时"         # 用户原话
  window_hours: 72                  # 解析成小时数
  filter_strategy: hard_filter | soft_sort | failed
  # hard_filter: 有 published_at → 按 window_hours 硬过滤
  # soft_sort:   无 published_at 但有 Score → 按 Score 降序作为热度代理
  # failed:      既无 published_at 也无 Score → 标 FAILED + 保留全部
  results:
    total: 40
    in_window: 12                   # published_at 在 72h 内的数量
    out_of_window: 23               # published_at 超出 72h 的数量
    unknown_time: 5                 # published_at 缺失的数量
  action_on_filter:
    keep: in_window                 # 保留窗口内的
    mark_and_keep: out_of_window    # 标 `out_of_window: true` 但保留（不删，供人工判断）
    mark: unknown_time              # 标 `time_unknown: true`
```

### 4.5.3 元信息块补充字段

在 [§ 4.3.2](#432-必带元信息五件套) 元信息五件套基础上，时间窗场景额外补充：

```yaml
---
query: AI news in the last 72 hours
domain: social_media
sub_domain: social_media.social_media (type=reddit_post)
fetched_at: 2026-07-21 14:30:00 (UTC+8)
anysearch_cost_ms: 3210
source: AnySearch CLI v2.1.0
# 时间窗补充字段
time_window:
  requested: "72h"
  filter_strategy: failed           # social_media 域无 published_at → 标 failed
  in_window: 0
  out_of_window: 0
  unknown_time: 25
  note: "social_media sdp 不返回时间字段；建议走 extract 二次抓取详情页拿 created_at"
---
```

### 4.5.4 强制规则

- **识别到时间窗词必须处理**：不允许静默忽略（违反硬规则 8 + 15）
- **失败必须显式标注**：`time_window_check: FAILED` + 在元信息块说明原因 + 在报告正文提示用户
- **不删除超窗结果**：标 `out_of_window: true` 但保留（供人工判断；部分用户可能接受"近期+热度"的混合结果）
- **严格过滤走 extract**：用户明确要求严格 72h 过滤时，提示"social_media 域 sdp 不支持时间参数，需走 extract 二次抓取详情页拿 created_at，代价是 N 次额外调用"
- **finance/academic 域优先用参数**：话题相关时优先用 period/year_from，不走 failed 路径
