# 01 意图解释（环 1）

## 1.1 这一环解决什么问题

AnySearch 是参数化 API——`search "query" --domain X --sub_domain Y --sdp Z`。它听不懂人话："帮我查一下 AI 选题""研究一下这个博主""看看今晚有什么电影"。

**意图解释 = 把人话翻译成 AnySearch 看得懂的 schema。**

## 1.2 核心 Schema

```yaml
intent:
  raw_query:         # 用户原话，原文照抄
  goal:              # 实际目标（追问/推断后）
  required_fields:   # 必须回答的字段
    - field: <字段名>
      from: <user / assumed / domain_default>
      value: ...
  ambiguities:       # 待澄清的歧义点
    - field: <字段>
      question: <给用户的追问原文>
      priority: high|medium|low
  clarifying_q:      # 给用户的多轮追问（≤3 个，按优先级排序）
    - question: ...
      reason: ...
  missing_required:  # 必填缺失 → 阻断；非必填缺失 → 标 assumed
    - field: ...
      default: ...
  locked:            # 用户已答完，意图锁定，可进入环 2
    false
```

## 1.3 翻译四步法（翻译层核心方法论）

AnySearch 听不懂人话，但听不懂的原因不是 API 差，而是**用户给的话本来就不是 query**。翻译层做的事：把"Reddit 里 72 小时内的 AI 领域"翻译成 AnySearch 能精准搜索的 query + keyword + domain 组合。

方法论来源：AnySearch live API `initialize` 响应的 `instructions` 字段 + `tools/list` 的 `search` 工具 `description` 字段（非静态 doc_spec.md，详见 SKILL.md § 8）。

### 1.3.1 第一步：识别意图类型（Path A / Path B / Hybrid）

官方两条 first-class 路径，按 query 是否需要结构化字段选路：

| 路径 | 触发条件 | 调用形态 | 适用 |
|---|---|---|---|
| **Path A（通用搜索，一等默认）** | 非结构化查询 | `search(query="...")` 或 `batch_search`，不传 domain | 新闻/概念/人物/公司/URL 验证/最新事件/对比/观点/任何没有结构化标识符的查询 |
| **Path B（垂直搜索）** | 查询含结构化标识符 | 先 `get_sub_domains(domains=[...])`，再 `search` 带 domain/sub_domain/sdp | ticker/DOI/CVE/IATA/坐标/专利号等，或映射到专门垂类（股价/航班/论文/药品/天气/汇率/地理 POI） |
| **Hybrid（拿不准时）** | 模糊查询 | 同一个 batch_search 里 1 个 Path A + N 个 Path B | 模糊/两可查询；覆盖率优先 |

**官方原文**（live API instructions）：
> "Path A — General search (default for any non-structured query)... This is a first-class default — not a fallback or rare exception."
> "When unsure → Hybrid via batch_search. Fire one Path A query (general, no domain) AND one or more Path B queries (vertical, with domain) in the SAME batch_search call. Coverage beats guessing."

**反例（必须避免）**：
- ❌ 把"AI 新动向"直接塞 Path B 的 `sdp keyword=AI`（违反硬规则 12 + Path A 才是默认）
- ❌ 用 Path B 但不先调 `get_sub_domains`（违反硬规则 13）
- ❌ 把结构化标识符（如股票代码）塞进 Path A 的 query 自然语言（应该走 Path B 的 sdp）

### 1.3.2 第二步：keyword 具体化（禁用单泛词）

官方 `sdp.keyword` 字段描述：**"Search keywords take precedence over query fields"**——意思是 keyword 参数会覆盖 query 位置参数。这正面说明：keyword 写得好不好，直接决定返回结果质量。

**官方示例 keyword 全是多词具体短语**：
- `AI large models`（不是 `AI`）
- `Python developer`（不是 `Python`）
- `Musk`（专有名词，不是 `CEO`）

**具体化规则**：

| 类型 | ❌ 禁用（泛词） | ✅ 推荐（具体化） |
|---|---|---|
| 单字主题 | `AI` / `科技` / `新闻` | `AI large models` / `AI Agent tutorial` / `AI regulation healthcare` |
| 单字行为 | `教程` / `评测` | `Python decorator tutorial` / `Claude vs GPT comparison` |
| 平台泛词 | `小红书` / `Reddit` | `Reddit AI Agent discussion` / `小红书 AI 工具推荐` |
| 时间泛词 | `最新` / `最近` | `AI news July 2026` / `AI breakthrough last 72 hours` |

**具体化策略**（按场景）：
- 选题调研：`<主题> + <角度>`（如 `AI Agent 入门路径` / `AI 工具对比`）
- 博主研究：直接用博主名/ID（如 `<博主名>` / `@username`）
- 评论区挖掘：`<主题> + <痛点词>`（如 `AI Agent 踩坑` / `LangChain 学习路径`）
- 跨平台对比：`<主题> + <对比维度>`（如 `Claude vs GPT coding` / `AI 工具评测`）

### 1.3.3 第三步：多域 rephrase（官方 Pattern 2，同主题跨域时用）

官方多域策略分两种 Pattern：

| Pattern | 触发条件 | 策略 |
|---|---|---|
| **Pattern 1（并行域）** | 一个请求问多个独立话题 | batch_search 每个域不同 query |
| **Pattern 2（交叉域，默认用于模糊查询）** | 一个主题跨多个域 | batch_search 每个域**同一个核心问题换角度** |

**Pattern 2 是翻译层的核心方法**——不是把用户原话直接塞 keyword，而是按每个域的视角重新表述。

**官方示例**：
> 主题："AI regulation's impact on healthcare investment"
> - finance 视角：`"AI regulation impact on healthcare investment trends 2025"`
> - health 视角：`"healthcare AI regulatory compliance requirements"`
> - legal 视角：`"AI medical device regulation legal framework"`

**翻译决策模板**：
```yaml
multi_domain_rephrase:
  core_topic: "用户原始主题"
  domains:
    - domain: <域1>
      rephrase: "<从域1视角重新表述>"
      why: "域1 关注 X 角度"
    - domain: <域2>
      rephrase: "<从域2视角重新表述>"
      why: "域2 关注 Y 角度"
```

### 1.3.4 第四步：单一意图校验（ONE intent per search call）

官方硬规则原文：
> "ONE intent per search call. Split multi-intent queries with batch_search."
> "query is pure natural language. Structured params → sub_domain_params, NEVER in query."

**校验规则**：
- 每个 search 调用只承载一个意图
- 多意图必须拆成 batch_search 的多个 query
- 结构化参数（type/keyword/region/period 等）走 sdp，不写进 query 自然语言
- query 是纯自然语言，sdp 是结构化参数，两者职责分离

**反例**：
- ❌ `query="Reddit 上 AI Agent 教程 type=reddit_post"`（结构化参数混进 query）
- ❌ `query="AI Agent 教程和 LangChain 实战"`（一个 query 两个意图）
- ✅ `query="AI Agent tutorial" + sdp="type=reddit_post,keyword=AI Agent tutorial"`
- ✅ 拆成 batch_search：`[{query:"AI Agent tutorial"}, {query:"LangChain 实战"}]`

### 1.3.5 翻译 checklist（执行前自检）

每条 query 落地前必须过这 5 条自检：

| # | 检查项 | 通过条件 |
|---|---|---|
| 1 | 意图类型已识别 | 标了 path_a / path_b / hybrid |
| 2 | keyword 具体化 | 不是单泛词；是多词短语或专有名词 |
| 3 | 多域 rephrase（如适用） | 同主题跨域时每个域换了视角 |
| 4 | 单一意图 | 一个 query 只承载一个意图 |
| 5 | 结构化参数走 sdp | query 是纯自然语言，不含 type=/keyword=/region= 等 |

**违反任一条 = query 未通过翻译层，不允许进入环 2 路由**。

## 1.4 澄清规则

### 1.4.1 必填缺失直接问，不脑补

例：
- 用户："搜一下今晚的电影票"
- Skill 追问：① 哪部电影？② 哪个城市？③ 几点场次？
- ❌ 不能默认"今晚 8 点 + 北京 + 最新上映"，那是脑补不是追问。

### 1.4.2 一次最多问 3 个问题

按"是否能定 query > 能否定 domain > 能否定 sdp"顺序排：

```text
P0（必问）：决定 query 本身能不能写
  例：电影名 / 博主 ID / 选题主题
P1（重要）：决定 domain 和 sub_domain 选哪几个
  例：海外还是国内？小红书还是 X？
P2（次要）：决定 sdp 细节
  例：X 是查 top 还是 latest？Reddit 是查 post 还是 comment？
```

超过 3 个问题就拆成多轮对话，每轮 ≤3 问。

### 1.4.3 用户答"随便/都行"→ 启用 fallback

每个 domain 都有 `domain_map.yaml` 里写的 fallback 默认值。标 `assumed: true` 让上层知道"这是默认值"。

例：
- "随便" + 选题调研 → fallback: `social_media` 全子类型 + `academic.search` 1 条
- "随便" + 博主研究 → fallback: `social_media.zhihu` + `general` + `social_media.wechatmp`

### 1.4.4 意图锁定的标志

`locked: true` 表示：
- 所有 `P0` 问题已答
- 或用户显式说"先这样 / 跑一下"
- 锁定后才进入环 2 路由

## 1.4 澄清话术模板

不同场景下的标准追问话术：

| 场景 | 必问 | 重要问 | 次要问 |
|---|---|---|---|
| 选题调研 | 主题？ | 平台范围（海外/国内/全）？受众画像？ | 时间窗（本周/近 30 天）？ |
| 博主研究 | 博主 ID 或平台主页？ | 主要活跃平台？调研目的（学习/竞品/合作）？ | 时间窗？ |
| 配图采购 | 主题或关键词？ | 用途（封面/插图/背景）？商用还是学习？ | 风格（极简/写实/插画）？ |
| 跨平台对比 | 关键词？ | 平台范围？ | 排序字段（热度/时间/互动）？ |
| 评论区挖掘 | 主题？ | 平台（Reddit/知乎/微博）？ | 关注痛点 vs 关注话题？ |

## 1.5 示例：选题调研意图锁定

```yaml
user_raw: "做本周 AI 选题调研"
intent:
  raw_query: "做本周 AI 选题调研"
  goal: "本周 AI 相关选题热点跨平台调研"
  ambiguities:
    - field: 主题范围
      priority: high
    - field: 平台范围
      priority: high
    - field: 受众
      priority: medium
  clarifying_q:
    - question: "主题是 AI 全行业还是某细分（Agent / 编程 / 提效）？"
      reason: 决定 query 怎么写、sdp 怎么选
    - question: "平台范围：只国内 / 只海外 / 全都要？"
      reason: 决定 domain 选哪几个
    - question: "受众是开发者、内容创作者还是大众？"
      reason: 决定优先级排序权重
  locked: false
```

用户答完后（假设"AI Agent / 全平台 / 内容创作者"）：

```yaml
intent:
  goal: "本周 AI Agent 相关选题跨平台调研（内容创作者视角）"
  required_fields:
    - { field: 平台, value: 全（X+Reddit+公众号+微博+知乎）}
    - { field: 主题, value: AI Agent }
    - { field: 受众, value: 内容创作者 }
  locked: true
```

锁定后进入环 2。

## 1.6 与其他环的契约

**环 1 输出 = 环 2 输入**。环 2 路由表完全基于 `required_fields` 决定，不重复追问。
