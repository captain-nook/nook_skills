# nook-wiki — 个人生产型知识库工作流 Skill

> **让个人知识库从“剪藏堆积场”转变为“高保真、可随时调用、能自生长的选题发动机”。**

做内容的人往往存了成百上千篇长文，但真到写稿、录视频时：
- 要么完全想不起自己存过什么；
- 要么把全文扔给 AI 暴力做 RAG 检索，AI 吐出一堆看似头头是道、实则张冠李戴的幻觉拼贴；
- 要么每次选题凭空抓瞎，不知道库里的原料到底能支撑哪些硬观点。

`nook-wiki` 是一套完整的个人生产型知识库编排 Skill。它不搞黑盒向量数据库或暴力 RAG，而是通过严苛的**原子解构、保真校验与双链话题沉淀**，将外部输入安全转化为随时可调用的卡片网络，并直接驱动选题创作。

---

## 核心设计与真实踩坑教训

这个 Skill 里的每一条死规矩，都是在实际生产中踩过真坑后用血泪总结出来的：

1. **单篇单文件推进，绝不用脚本批量批处理**
   - *真实踩坑*：早期曾用 Python 脚本批量读取 50 篇原文并让 LLM 自动切卡，结果核对发现：59 句标注为“原话引用”的内容里，有 17 句在原文中根本不存在，全是被大模型擅自跨段拼接或脑补出来的“伪原话”。
   - *机械约束*：必须用 Agent 自带的文件工具逐篇通读、逐篇自检。前一篇写好的卡片立即入库，后一篇比较时便能立刻形成双向链接。

2. **严格分离四种声音（谁在说话绝不混淆）**
   - 卡片正文中必须清晰区隔：
     - **原话**：必须是同一段落内连续、一字不改的文字，带原作者署名；
     - **转述**：客观叙述，作者说“可能”绝不写成“一定”；
     - **推断**：Agent 自身的综合判断，强制标明 `【推断】`；
     - **创作者的话**：用户自己的亲历与思考，开头标 `【创作者】` 一字不改收录。
   - *真实踩坑*：曾有一张卡片把原作者自己的比喻，擅自提炼并归属成了“Karpathy 认为知识库像编译器”。这种张冠李戴在公开发布后会造成严重的名誉与事实硬伤。

3. **话题页防翻转机制（综合不等于强行归纳）**
   - 话题页的门槛极其严苛：**至少有 2 位独立作者的卡片实质性探讨该问题，才允许建页**。只有单作者观点时，卡片再多也不建页，只保留双链。
   - *真实踩坑*：在多来源综合时，大模型极其容易把“指标对象”搞反。例如在实际质检中，AI 曾把卡片里的“AI味浓度不高于 40%”在话题页里概括成了“独有信息占比不高于 40%”——数字一致，但限制对象与方向完全说反。本 Skill 建立了针对指标限制方向的专项自检。

4. **按“能回答什么问题”聚合，拒绝按章节平铺**
   - 一篇长文离开原文后，只有能作为**依据、案例、反例或实操方法**的内容才值得成卡。
   - 若候选卡片与文章目录几乎一一对应，判定为“机械切碎”，强制要求按解决的核心问题合并。

## 包含的三大核心能力

无需拆成三个零散的 Skill，`nook-wiki` 统筹并根据指令自适应流转：

| 模式 | 常用触发词 | 核心职责 |
|---|---|---|
| **Ingest（提炼入库）** | 「整理一下」「入库」「清库」「处理这几篇文章」 | 逐篇解构剪藏原文，比对已有库、写卡、原话防伪自检、跨作者建话题页、记日志。 |
| **Query（选题推导）** | 「找选题」「这期写什么」「看看能写什么」「想做个关于...」 | 问出创作者亲历与真实想法，在库内调动正反证据，推导 2~3 个有真实差异的方向，生成结构化选题卡。 |
| **Lint（质量体检）** | 「检查Wiki」「体检」「查查知识库」「检查链接」 | 机械检查断链、单向链接、未建页话题；抽查原话连贯性、数据口径一致性与指标翻转。 |

## 目录结构与解耦机制

本 Skill 经过完全解耦，**不绑定任何私有路径**。无论是标准的 Obsidian 库，还是任意 Markdown 文件夹，只要满足或映射以下基本结构即可开箱即用：

```text
你的知识库根目录/
├── 01_Clipper/       # [输入] 网页剪藏原文（只读，或命名为 Clipper/）
├── 00_Inbox/         # [速记] 创作者灵感、亲历或临时想法（或命名为 Inbox/）
├── 02_Wiki/          # [知识库] 原子卡片与话题页平铺处（或命名为 Wiki/、Notes/）
│   ├── _index.md     # 索引导航文件（自动维护）
│   └── _log.md       # 处理与检查日志（单向追加，自动维护）
├── 03_选题/          # [输出] 结构化选题卡（或命名为 Topics/）
└── profile.md        # [可选] 创作者画像与风格硬规矩（见 profile.example.md）
```

> **自适应说明**：
> - 文件夹名称带不带数字前缀（如 `01_Clipper` vs `Clipper`）均可自动识别。
> - 若库内没有内置 Schema，本 Skill 会直接无缝加载自带的 `references/schema.md` 作为统一判据。
> - 若根目录下没有 `profile.md`，可参考包内附带的 `profile.example.md` 建立，未配置时自动采用通用的客观严谨准则。

## 安装方法

### 方式 A：Git Clone（推荐）

```bash
git clone https://github.com/captain-nook/nook_skills.git
```

将 `nook_skills/nook-wiki` 整个目录复制到对应 Agent 的 Skills 目录下：

| 平台 / Agent | 目标目录 |
|---|---|
| **Antigravity / Gemini** | 工作区根目录下的 `81_Skills/nook-wiki`，或全局配置目录 |
| **Claude Code** | `~/.claude/skills/nook-wiki` |
| **Codex** | 放进项目目录即可，会自动识别 `SKILL.md` 与 `agents/openai.yaml` |
| **Cursor / Windsurf** | `<workspace>/.skills/nook-wiki` |

### 方式 B：手动下载
在 GitHub 仓库中单独下载 `nook-wiki` 文件夹放入你的 Skill 目录。

## 使用指南

### 1. 批量入库（Ingest）
向 Agent 说：
> “把这周剪藏的文章整理入库” 或 “处理一下 Clipper 里的这篇《xxx.md》”

- Agent 会首先比对 `_log.md` 识别待处理增量与未完成的半成品；
- 汇报批次计划并等待你确认；
- 逐篇通读、比较已有卡片、成卡并立即自检原话；
- 每篇处理完即时播报，整批结束后提供抽查复核报告。

### 2. 启发式选题（Query）
向 Agent 说：
> “根据库里的材料，看看这期能写什么选题” 或 “我想聊聊知识库搭建，帮我推导几个切口”

- Agent 不会凭空脑补选题，而是会首先向你提问，原样记录你的个人经历与最想说的一句话；
- 从库内话题页与卡片中调取强相关论据，并寻找反例与适用边界；
- 输出 2~3 个有真实差异的选题方向，确认后自动在选题目录生成标准选题卡。

### 3. 全面体检（Lint）
向 Agent 说：
> “给知识库做一次全面体检” 或 “检查一下最近一批入库卡片的链接与原话”

- 自动扫描断链、单向缺失的双链、符合建页条件但尚未建页的话题；
- 抽查卡片原话是否在原文连贯存在、关键数据指标是否出现正反翻转；
- 机械错误自动修复并留痕到 `_log.md`，主观性改动列出清单交由你拍板。
