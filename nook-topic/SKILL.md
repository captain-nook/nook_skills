# nook-topic — 选题提炼

## ⛔ 触发即全量 —— 采集契约是刚性约束，不是建议

**本 skill 一旦被触发，必须先读 [[references/采集契约]] 并按它全量执行 12 个通道。**

三条铁律（违反即本次驱动无效）：

1. **触发即全量**：12 通道逐个跑，不由 AI 判断"这次用不上"。**必须输出覆盖率报告（X/12），缺一个显式说明原因。**
2. **判断权归人，AI 不得剔除**：噪声、擦边、"看起来跟受众无关"的一律**保留并标注来源**。
   AI 看着无关的一条新闻，可能正是用户近期在关注、或被反复问到的——**AI 不知道，所以无权删**。
3. **一轮一笔记**：全平台全关键词汇总进**同一个**笔记，不按平台/关键词分文件。英文补中文摘要。

**为什么要写死**：260726 实测，12 个通道只跑了 6 个——X / Reddit / 知乎 / 微博 / 公众号五个全漏，而它们全都可用。
原因是"采哪些平台"只存在于 AI 的记忆里，不在文件里，于是每次跑什么取决于当次想起什么。

**本 skill 的产物是「材料」不是「结论」。** AI 负责把鱼全捞回来、按来源标注、英文翻中文摘要；
**选哪条是人的事**，或人机共同判断。AI 直接给出"本周就做这个"= 越权。

## ⚡ 怎么跑

本 skill 只做**判断层**（脚本采 → **AI 判** → 人定），不含采集脚本。
下面的命令名是**示例**，代表"一条命令跑齐多通道、落进同一个轮次文件、输出材料摘要"这个契约——
换成你自己的采集工具，只要能满足这个契约即可：

```bash
# 示例：单方向定向采集
your-collector --direction "AI 写作" --en "AI writing workflow"

# 示例：全量一轮（12 通道，先看计划再决定）
your-collector --sweep --dry-run
```

> **路径不要写死盘符。** 采集脚本换机器就废是最常见的坑——用哨兵文件或环境变量定位主库，
> 不要在脚本里硬编码绝对路径。
> 任何会触发真实网络请求/写盘的编排脚本都应该有 `--dry-run`——没有的话，
> 任何人想看它怎么跑都会直接触发一次真实执行。

一条命令跑齐若干通道（下面 §采集契约 里给了一套可参考的 12 通道穷举），
落进同一个采集轮次文件，输出**材料摘要**。

**然后必须做第二段**：读摘要 → 按 [[references/选题单模板]] 的四步判断（受众关 → 噪声剔除 →
语义聚类 → 找空隙）→ 填出**选题单** → 交人定。

**架构 = 脚本采 → AI 判 → 人定。** 三段缺一不可：
- 只有第一段 = 采集器，产物是材料不是选题，没省下判断成本
- 语义判断写不成 if-else（"这条属不属于我的赛道""这个角度有没有人讲过"），**必须 AI 做**
- AI 不拍板，最终选择权在人

输出契约（选题单格式 + 四步判断细则 + 硬规则）= **[[references/选题单模板]]，出单前必读**。


把采集信号 + 可选本地素材 + 上周数据，提炼成 3-5 个选题方向。方向是"值得做一组内容的主题角度"，不是具体某条稿。大调性恒为 **AI 提高生产力**。

选题是整条内容链最源头、最难的能力。**核心方法论(判断/差异化角度/证据先行)见 references/选题的判断与角度.md，动手前必读。** 下面的公式和格式是骨架，那份文件是灵魂。

**证据弹药库（你自己维护）**：把你已经产出过的长内容（视频/文章/项目）拆成可跨平台裂变的价值点，
按母题聚类。选题第一步来这里挑还没裂变的价值点（证据/画面素材现成），配当周热点，按平台裂变。
这是创作者选题的地基——本仓库不附带具体清单（那是你自己的内容资产），
但强烈建议按 `选题的判断与角度.md` 里"证据先行"一节的方法自建一份。

**三源方法论**：证据源（你做过的内容）定"我能讲什么"，深度源（你自己的长文/长推收藏库）定
"值得深讲什么"，时机源（新闻/RSS）定"什么时候讲正好"。具体的采集命令因人而异，
方法论见 `选题的判断与角度.md`。

**采集方法论 = references/采集方法论_v1.md**：24 维度撒网+三层搜索+7 字段标注去重的操作手册，含 B7 补强（4 层水源/痛点词占比/4 问快速过滤/公式前置/3 条认知警觉）。采集日和定菜谱日的硬规则都在这里。

**⛔ 关键词怎么设计 = [[references/关键词设计推导]]，改词/加词/删词前必读。** 回答"为什么是这些词、
不是 Obsidian / Claude Code / 写作方法 / 搭一套AI系统"。核心：**关键词的所有权在受众嘴里，不在创作者手里**——
工具名召回同行生态，症状词召回受众。机械判据 = 填进「我______，怎么办？」填不通就不进表。
260727 之前这套推导只存在于对话里、不在文件里，后果是词表不可辩论、不可扩展、不可交接。

## 核心认知(先记住,否则后面全是走过场)

1. **选题是预测不是分析**。目标不是"选出必爆的题"(不可能)，是提高命中率 + 控制风险 + 快迭代。它是概率游戏。
2. **信号 ≠ 选题**。采集给的是信号，从信号到选题隔着"判断"。别把"这个题火"当成"我要做这个"——火的是别人的答案，你要找的是未满足的需求或你能给的不同答案。
3. **判断=五关**：需求验证 → **供给独特(差异化，最关键)** → 证据支撑 → 人设一致 → 时机。大部分信号在"差异化"和"证据"两关死掉，这是健康筛选。
4. **证据先行**：先盘你手里真实的项目/经历/结果(选题弹药库)，再从证据找选题；不是定个热门题再硬凑证据(那必成空谈/手册)。
5. **差异化角度是护城河**：创作者的护城河=亲自下场的真实证据 × "人定方向AI执行"的观点框架。优先选能发挥这个护城河的题。
6. **对标 AI 博主 ≠ 对标我的受众**（260726 实战踩坑，代价最大的一次）。采集通道（YouTube 撒网/信号雷达/B站低粉爆款）采的是**AI 博主生态**，而 AI 博主的受众是 AI 爱好者，**不是自媒体工作者/超级个体**。当天五源共识齐刷刷指向"Agent/Skill 系统"母题，据此出的三个候选被用户全否——因为受众根本没搭过系统。**信号强 ≠ 受众要**。
   - **硬规则：任何候选进入五关之前，先过受众关**——这条内容的受众是不是"靠内容吃饭、痛点是产能低和不知道发什么"的人？不是就砍，信号再强也砍。
   - **你自己手动收藏的长文库是唯一天然贴近受众的源**（你手动收藏的东西，本身就代表这个受众关心什么），权重应高于自动采集源。当天正确的信号（"选题"独立出现 3 次）就在这个源里，被"五源共识"压掉了。
7. **⛔ 技术控偏置：手上最新鲜的证据，往往是你刚做完的技术活**（260727，当天写完规则当天就犯）。
   证据先行是硬要求，副作用是**它把选题往供给侧拽**——刚修完采集器，脑子里全是采集器。
   当天实例：我推荐了三个中视频题，两个是「采集被警告怎么办」「能跑≠在你机器上能跑」，
   还提了个「我搭了套选题系统跑完 433 条」的架构。**那是工作日志，不是受众痛点。**
   受众没有 12 个采集通道，他们只有"我不知道发什么"。
   - **机械判据（交付物可用性测试）**：这条内容的交付物，一个**不写代码、不装环境、
     只有手机和微信**的自媒体人，能不能直接用？不能 = 技术控，砍。
   - **技术活可以当证据，不能当选题。** 必须先把它翻成受众的症状，技术过程降级成佐证数字：
     「我跑了 433 条发现 80% 没用」→ 选题是「**为什么你天天刷同行，还是不知道发什么**」，
     433 这个数字只出现在证据位，不出现在标题和钩子里。
   - 这条和第 6 条（对标 AI 博主 ≠ 对标我的受众）是同一个病的两个变种：
     第 6 条是**采集源**偏向同行生态，本条是**证据**偏向自己的技术活。
8. **验证热度 ≠ 验证受众**（260727）。「这个题是不是热点」和「问的人是不是我的受众」是两件事。
   反例：「收藏了从来不看」提问数 7（热度极真实），赛道外数 9（问的人是焦虑的普通读者）。
   **顺序必须是：受众关 → 热度验证 → 五关。** 热度再高也不能给受众关免票。
9. **受众动机二分：替代 / 放大**（260727，源自瑞秋Grandma 起号脚本）。
   受众分两类——①喜欢做，想用 AI **放大**效果 ②讨厌做，想用 AI **代替**自己做。
   **同一个卡点，两类人的交付物完全相反**（「写不出来」+喜欢写=怎么写得更好；+讨厌写=怎么不用自己写）。
   出选题时必须标明这条打的是哪一类，否则钩子和交付物会错配。已落进关键词矩阵第二维。
10. **受众要结果，不要过程**（260726）。钩子必须是**具体结果**（"3 千粉一条视频 7 万 5 播放"），不是机制描述（"我扒了 36 个账号发现规律"——这是在解释机器怎么工作，观众一秒都不等）。**没有自有结果时，结果可以来自研究对象**，你的角色是发现规律的人；但数字必须真实可自查。

## 定位原则

- **live 车道（平台样本 × 新闻热点）是短内容选题的主力驱动。** anchor（中视频/项目素材）是偶尔加分项：恰好与 live 信号交汇才纳入，某周没有 anchor 是正常状态，不算风险，不得为凑 anchor 降低方向质量。
- **平台优先 + 产出反推**：采样平台必须=产出平台。B站/YouTube 数据只当赛道需求温度计，不决定短内容形式和钩子。
- 中视频（长视频线）与公众号（深度观点线）的选题不走本 skill，各有自己的选题库。

## 输入(四源,重新理解)

```yaml
distill_input:
  需求侧:          # 什么题有人要 —— 平台爆款 + 【评论区反复在问的问题/搜索不满意的题】(最强需求信号,见方法论第四节)
  供给侧:          # 什么题我能做出差异化 —— 你的真实项目/经历/证据(选题弹药库,证据先行)
  时机侧:          # 什么题现在做正好 —— 新工具/新事件/热点窗口
  人设过滤:        # 什么题符合创作者 —— 你自己的账号人设文档划边界（本仓库未附带，替换成你自己的定位文档）
  last_week_review:  # 上周 90_复盘 的 keep/kill,作为下周选题先验
```

**评论区需求是被低估的最强源**：火的内容是别人已给的答案，评论区反复问的才是未满足的需求(明确、蓝海、自带钩子)。小红书采集受限时尤其倚重这个源(人工刷评论区即可，不需爬取)。

## 筛选公式

**选题价值 = 市场热度（平台样本）× 时机（新闻热点）×（可选加分：证据强度 anchor）**

口诀：平台样本定"怎么讲"，新闻定"什么时候讲"，anchor 若有则加分定"讲得更实"。

优先级：样本×新闻交集（主力）> 三源交集（anchor 恰好命中，最优但非必须）> 单纯样本（降权可用）> 单纯新闻（须有自己判断角度，每周 ≤1-2 条，不做搬运）> 纯 anchor（原则不立项，除非 growth_logic 极强）。

## 去重与信号解读

- 跨批次重复的样本带 `dedup.seen_count`：**复现≠垃圾，是持续热度信号**，seen_count 高的母题加权。
  ⚠️ seen_count **只在同一通道内部可比**，且索引需已同步（见采集契约 §2.6）。
- **⛔ 反向规则：单条爆款 ≠ 规律**（260727）。一条内容数据好，只证明这一条成立，
  不证明它背后的方法成立。要当规律用，必须**在多个样本里重复出现**，或**在自己的数据里被独立印证**。
  - 260727 正例：瑞秋Grandma 的「喜欢做/讨厌做」二分被采纳，理由不是她那条笔记 1035 赞，
    而是它在我们自己的 Reddit 数据里被独立印证了（两组同为 10/0/0 的词，一组在求救一组在取经）。
  - 反面姿势：看到一条爆款就提炼方法论。**那是从 n=1 归纳。**
  - 判据：写进方向的 `differentiation` 之前，问一句"这个规律我有几个独立样本？"
    只有 1 个 → 降级成"待验证假设"，可以做内容，但不能当方法论卖。
- 语义聚簇（不同措辞同一母题）是本 skill 的本职工作，人工/agent 判断，不做自动化。

## anchor 资产抽取（仅当本周有 anchor 素材时）

对每份 anchor 素材抽资产并评级（none/weak/mid/strong）：result（做出了什么，有无可见画面）/ pain / pitfall / viewpoint / case / list / process。strong=有真实证据直接支撑；weak=只有想法；none=对应内容模型禁用。评级结果写进方向的 evidence_ready。

## 拒绝过滤

降权或拒绝：AI漫剧、AI短剧、AI特效、AI换脸、AI美女、纯AI生成奇观、无关娱乐、无角度泛新闻。
保留：能迁移到口播/教程/工作流/图文的样本（AI工具、AI编程、Agent、自动化、提示词、知识管理、普通人可执行案例）。

## 各平台好样本判据（产出反推）

| 平台 | 找什么 | 判据 |
|---|---|---|
| 抖音 | 强钩子、情绪反差、猎奇开场 | 完播率、点赞率、评论情绪浓度 |
| 小红书 | 封面公式、可收藏清单、搜索词 | 收藏率、搜索排名、封面点击率 |
| 视频号 | 身份认同点、共鸣观点 | 转发率 |

## 输出契约（3-5 个方向）

每个方向必须能回答"为什么是本周做、凭什么涨粉"：

```yaml
direction:
  name:            # 方向短名
  slot:            # 【配额】基本盘(中视频) / 拆解 / 补充 —— 见你自己的周规划算法/配额规则
  audience_gate:   # 【最先过】受众是不是"靠内容吃饭、痛点是产能低+不知道发什么"的人？不是就砍
  no_code_test:    # 【最先过·第二问】不写代码/不装环境、只有手机和微信的自媒体人能不能直接用？
                   #   不能 = 技术控，砍（见核心认知第 7 条）。技术活只能填进 evidence，不能当 name
  motive:          # 【替代 / 放大】打的是"讨厌做想代替"还是"喜欢做想放大"？决定交付物形态
  selected:        # 【G1 闸·人工填】选中打 ✅。AI 不得自己填。留空 = 写作 skill 不得开工
  platform_locked: # 【G2 闸·人工填】锁定产出平台，如 [中视频, dy, xhs]。留空 = 形态未定，不得开工
  demand:          # 需求验证：谁在要？证据是什么(评论区问题/搜索/爆款数据)
  differentiation: # 【差异化角度，最关键】和现有内容不一样在哪？一句话说清独特角度
  evidence:        # 证据支撑：我有什么真实项目/经历/结果撑这个题(没有=空谈,砍)
  persona_fit:     # 人设一致：怎么扣到创作者"人定方向AI执行"
  why_now:         # 时机：为什么现在做正好
  growth_logic:    # 陌生人为什么停留/关注
  fit_platforms:   # 适合哪些平台、什么形式(同母题各平台不同角度)
  green_or_hot:    # 常青 / 热点(用于批量配比)
  est_items:       # 预计能出几条(证据够几条报几条)
  risk:            # 疲劳/证据/平台风险
```

**每个方向必须能过五关**：demand(需求)、differentiation(差异化)、evidence(证据)三关任一空缺=不合格，砍掉或搁置补齐。差异化和证据是创作者选题的命门。

**本 skill 的产物停在人工确认之前。** 选题单交付时 `selected` / `platform_locked` **必须留空**——
它们是人填的闸位标记。**AI 自己填 ✅ = 越权，等于取消了这道闸。** 填完选题单就停，等人回话。
（如果你有自己的确认闸/审批流程系统，把这两个字段接到那套系统里。）

## 提炼规则

1. 优先"平台样本×新闻热点"交集，不依赖 anchor。
2. 纯新闻方向 ≤1-2 个，必须有自己判断角度。
3. 上周复盘结论直接生效：好母题延续，差模板降权。
4. 方向差异化：3-5 个方向至少 3 个不同母题。
5. `est_items` 合计应 ≥12（数据不足时如实说明，不硬凑）。
6. 数据缺口必须显式声明（如某平台样本缺失），不假装信号齐全。

## 提交格式

1. 本周需求摘要（3-5 句：市场在要什么、评论区在问什么、搜索缺什么）
2. 我的选题弹药库（我最近真实做了/跑通了/踩了什么，可撑哪些题）
