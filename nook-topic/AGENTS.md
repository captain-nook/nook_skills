# AGENTS.md — nook-topic 入口

给 Codex / Claude Code / 其他 Agent 读的入口文件。会话开始时自动读取。

## 什么时候触发这个 skill

用户说以下任意一种，就走 `SKILL.md` 的流程：

- "帮我找选题" / "关键词 XXX 有什么选题"
- "本周做什么内容" / "这批素材值不值得做"
- "帮我看看这个选题行不行"
- "这批采集样本里挑几个方向"
- "我的关键词设计得对不对"

## 执行顺序（不要跳步）

1. **先读 `SKILL.md`** —— 核心认知 10 条、五关判断、输出契约都在里面。
2. **改词/加词前必读 `references/关键词设计推导.md`** —— 关键词不是拍脑袋想的，有机械判据。
3. **出单前必读 `references/选题单模板.md`** —— 输出契约，四步判断顺序不可乱。
4. **采集能力见 `README.md` 的「采集依赖」节** —— 本 skill 自带零配置的 B站低粉爆款脚本，
   其余通道按 README 里的选项接。

## 三条硬规则（违反即本次驱动无效）

1. **受众关先于一切**：候选进五关之前先问"这条内容的受众是不是我要的那批人"。信号再强，受众不对就砍。
2. **AI 不拍板**：输出 2-3 个候选，`selected` / `platform_locked` 字段留空，等人填。AI 自己填 = 越权。
3. **技术活只能当证据，不能当选题**：过 `no_code_test`——不写代码、不装环境的人能不能直接用这条内容的交付物？

## 第一次用之前

编辑 `profile.md`（从 `profile.example.md` 复制一份），填你自己的赛道、受众、人设、已发布过的选题。
这份档案决定"受众关"怎么判——不填的话 AI 只能用通用判据，个性化程度大打折扣。
