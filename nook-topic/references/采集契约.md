# 0 为什么要有这份契约

在此之前，"采哪些平台"只存在于 AI 的记忆里，不在任何文件中。后果是**每次驱动跑什么，取决于当次想起什么**：
260726 实测——12 个通道只跑了 6 个，X / Reddit / 知乎 / 微博 / 公众号五个全漏，而它们全都可用，纯粹是忘了。

**本契约把清单从记忆搬进文件。触发即全量，缺一个必须显式报告，不允许静默跳过。**

# 1 ⛔ 三条铁律

1. **触发即全量**：12 个通道逐个执行，不由 AI 判断"这个通道这次用不上"。
2. **判断权归人，AI 不剔除**：噪声、擦边、"看起来跟受众无关"的条目**一律保留并标注来源**。
   AI 可以标记疑似噪声，**但不得删除**——某条在 AI 看来无关的新闻，可能正是用户近期在关注、或被反复问到的东西，AI 不知道。
3. **一轮一笔记**：所有平台、所有关键词的成果**汇总进同一个笔记**，不按平台/关键词分文件。
   英文内容**保留原文 + 补中文摘要**；中文原样保留。
4. **遇卡点必须发起动作并等待，不许绕开**：碰到"需要人来做"的环节（打开浏览器、扫码登录、
   装依赖、填 key、授权），**当场把请求提给用户并停在那里等**，做完继续跑。
   **严禁**"这个有点麻烦，先放一放，我们往下走"——那等于又回到"12 个通道只跑 6 个"。
   卡点解决不了时，在覆盖率报告里标 ❌ 并写明**卡在哪一步、需要谁做什么**，不许含糊带过。

5. **⛔ 卡点 ≠ 安全决策停用。两者处理方式相反，不许混为一谈**（260727 补）。
   - **卡点**（登录过期、依赖没装、key 没填）= 技术障碍，按铁律 4 推进，请人做完继续跑。
   - **安全决策停用**（平台警告后退役、用户主动暂停）= 已经做过的判断，**不许"为了凑满 12 个"去推进**。
     在覆盖率报告里标 `⛔ 停用` + 决策日期 + 决策原因，**这算通道全覆盖，不算漏**。

   > **为什么必须写这条**：260726 契约写"12 通道触发即全量、缺一个必须报告"，
   > 而同一天 `collect.py` 里小红书已因平台两次警告硬退役、抖音已被用户决策暂停。
   > 两份文件互相矛盾的后果是：下一轮无论怎么跑都"漏 2 个通道"，
   > 于是要么每轮背一个假的失败，要么有人为了达标去解开一个安全锁。
   > **契约不能要求代码违反安全决策。** 停用是覆盖率的一种合法结果。

## 2.4 ⛔ 小红书/抖音有两条路，只有一条能走（260727 实测确认）

这两个平台上**同时存在两套机制**，混淆它们是 260726 契约与代码互相矛盾的根源：

| 机制 | 怎么工作 | 状态 |
|---|---|---|
| **MediaCrawler CDP** | 脚本驱动一个**专用 profile** 的 Chrome 自动浏览/翻页 | ⛔ **小红书已退役**（平台两次警告采集小号"使用第三方工具或脚本自动浏览"，第三次大概率封号）<br>⛔ **抖音已暂停**（260726 用户决策，同机制预防性停用） |
| **`opencli <site> search` 适配器** | Browser Bridge，但适配器**自己开/导航标签页**，撞登录墙就反复弹登录 | ⚠️ 抖音可用；**小红书不要用**——260727 实测连续报 `AUTH_REQUIRED`，反复撞登录墙本身就是风险行为 |
| **`opencli browser <session> bind` 绑当前标签页** | 绑定**用户此刻正开着、已登录的那一页**，之后所有操作都在这一页内完成 | ✅ **小红书唯一正路**，260727 实测一次 eval 取回 20 条带标题/作者/点赞 |

**结论：这两个通道走 OpenCLI，不走 collect.py。** `collect.py --platform xhs/dy` 返回 `status: retired` 是**正确行为**，不要去解开它。

### 2.4.1 ⛔ 小红书标准操作：绑当前页，不新开、不弹登录

260727 教训（创作者原话："你又不停开，不停关，不停弹出登录验证，我的号又要被警告"）：
**agent 每新开一个标签页、每撞一次登录墙，都在给账号累加风险。** 而账号已经被警告两次。

正确流程 —— 前提是**用户自己已经在 Chrome 里开着小红书并登录好**：

```bash
# 1 绑定当前活动标签页（不新开、不导航）
opencli browser xhs bind
# 输出确认 url/title，必须是 xiaohongshu.com 才继续

# 2 在这一页内跳到搜索结果（open 走绑定的那一页，不新开标签页）
opencli browser xhs open "https://www.xiaohongshu.com/search_result?keyword=<urlencoded>"

# 3 一次 eval 取回整页结构化结果（不逐条点开）
opencli browser xhs eval '(()=>{const o=[];document.querySelectorAll("section.note-item, div.note-item").forEach(el=>{const t=el.querySelector("a.title");const a=el.querySelector("a.author, span.name");const c=el.querySelector("span.count");const l=el.querySelector("a[href*=\x27/explore/\x27]");if(t||l)o.push({title:(t&&t.innerText||"").trim(),author:(a&&a.innerText||"").trim(),likes:(c&&c.innerText||"").trim(),path:l?l.getAttribute("href").split("?")[0]:""})});return{n:o.length,items:o.slice(0,20)}})()'
```

**禁止**：
- ❌ `opencli xiaohongshu search`（适配器自己导航，会反复弹登录）
- ❌ `Start-Process chrome <url>`（新开标签页；Chrome 已经开着就永远不要再启动它）
- ❌ 程序化 `fill` 搜索框 + 点搜索按钮 —— 260727 实测填进去了但前端状态不认，不会导航，白点一次

**为什么用 `open` 而不是操作搜索框**：`fill` 能写进 textarea（`verified: true`）但触发不了前端搜索，
点搜索按钮也不导航。直接跳 `search_result?keyword=` 是一次导航拿到结果，动作最少。

### 2.4.2 前置条件（每轮开跑前检查，不要跑到一半才发现）

```bash
opencli doctor            # 必须 Extension: connected（Chrome 得开着，扩展才连得上 daemon）
opencli douyin whoami     # 抖音走适配器，必须 logged_in: true
```

- 用**用户自己的 Chrome**，绝不带 `--user-data-dir`。带了就是另一个浏览器实例，登录态不共享，
  这正是 260726 之前"每次都要重新扫码"的原因（`启动采集浏览器.cmd` 指了一个不存在的 profile 路径）。
- **小红书有两个域各自登录**：`creator.xiaohongshu.com`（whoami/创作者数据）与
  `www.xiaohongshu.com`（search）。登了前者不等于登了后者。
- 登录是**人的动作**，agent 不代填凭据、不代扫码。缺登录时把请求提给用户并等（铁律 4）。

### 2.4.3 ⛔ 评论区采集（通道 13，260727 新增，此前 433 条里 0 条）

**为什么单列成通道**：skill 从 260706 就写着"评论区需求是被低估的最强源"，
采集契约写着"值得单独跑"，**结果一年多从来没跑过**——因为它不是任何流程的一步。
和覆盖率报告同一个病：写了要用，没有产物，于是永远不做。

火的内容是别人**已经给出的答案**，评论区反复问的才是**未满足的需求**（明确、蓝海、自带钩子）。

**操作（在已绑定的标签页内完成，不新开）**

```bash
# 1 导航到目标笔记（复用绑定的那一页）
opencli browser xhs open "<笔记 URL>"

# 2 取评论。⚠️ 必须去重：.comment-item 和 .parent-comment 会双重匹配同一条
opencli browser xhs eval '(()=>{const seen=new Set(),o=[];document.querySelectorAll(".comment-item, .parent-comment").forEach(el=>{const a=(el.querySelector(".name, .author")?.innerText||"").trim();const c=(el.querySelector(".note-text, .content")?.innerText||"").trim();const l=(el.querySelector(".like .count")?.innerText||"").trim();const k=a+"|"+c;if(c&&!seen.has(k)){seen.add(k);o.push({a,l,c:c.slice(0,150)})}});return{n:o.length,items:o.slice(0,30)}})()'
```

**⛔ 选哪条笔记的评论区（判据，260727 实测得出）**

评论区价值**取决于笔记类型**，不是取决于点赞数：

| 笔记类型 | 评论区长什么样 | 值不值得采 |
|---|---|---|
| 求助 / 提问型 | 同类痛点扎堆，作者和读者互相补充 | ✅ **最高价值** |
| 教程 / 干货型 | "第 3 步卡住了""XX 情况怎么办" | ✅ 高价值，是需求缺口 |
| 个人经历 / 红利期型 | "感谢分享""你好漂亮""加油" | ❌ 社交性，无需求信号 |
| 清单 / 收藏型 | 评论极少（收藏走人） | ❌ 实测评论/点赞仅 2.4% |

> **260727 实测**：瑞秋Grandma 那条 1035 赞的笔记（个人经历+红利期型），
> 评论区 25 条里只有 1 条有信息量（"你平时用 Claude 多一点还是 codex 多一点"）。
> **点赞高 ≠ 评论区有料。** 采评论区要挑求助型和教程型的笔记。

**采集量**：一轮挑 **2-3 条求助/教程型笔记**的评论区，不要广撒网。
评论区是精读源，不是撒网源。

### 2.4.4 风险边界（小红书专用，比其他通道严）

- 只做**读取**（搜索结果页 / 笔记详情 / 评论），绝不做关注、点赞、发布
- **一轮最多 3 个关键词**，每词只取当前页（约 20 条），**不翻页、不滚动加载**
- 两次调用之间留间隔，不连发
- **一旦再收到平台告警，立即停用并在 §2.4 加一行记录日期**，不再尝试任何机制

## 2.5 ⛔ 通道分权（260727 补，此前 12 通道平权）

**12 通道平权穷举的后果**：260726 那轮 348 条里，过受众关的只有 60-70 条，
其余 80% 是噪声。判断权名义上归人，实际上归"谁有耐心扫完 348 条"——**扫不动就等于没判断**。

所以通道要分层，**层决定怎么读，不决定要不要采**（照样全量采，照样不删）：

| 层 | 通道 | 怎么读 |
|---|---|---|
| **受众源** | Supabase · Reddit · 小红书（含评论区） | **逐条读**。这三个源的作者/提问者本身就是受众 |
| **需求源** | 知乎 · 公众号 · X · 微博 | **只看聚类，不看单条**。同一个痛点出现几次比任何单条更重要 |
| **温度计** | B站低粉爆款 · YouTube低粉爆款 · 信号雷达 | **只看数字，不看内容**。判断赛道大盘和形式温度，不用来出选题 |
| **时机源** | RSS/news | **只在已有角度时用**，用来定"什么时候讲"，不用来定"讲什么" |

**为什么这么分**：判据是**这条内容的第一人称是谁**。
- 求助的人（Reddit 提问 / 知乎问题 / 用户手动收藏）→ 受众源
- 卖东西的人（SEO 文 / 课程推广 / 工具教程）→ 降权
- AI 博主讲给 AI 爱好者听 → 温度计，不是选题源

260726 实证：Supabase（用户手动收藏，天然是受众）和 Reddit（唯一带真人提问的源）
贡献了几乎全部可用信号；B站/YouTube/雷达/通用web 四个自动源接近零产出。
这和 SKILL.md 核心认知第 6 条是同一件事，这里把它落成可执行的分层。

## 2.6 ⛔ seen_count 的两个陷阱

1. **不可跨通道比较**。260726 news 那条 ESP32 跑 LLM 的 `seen_count=13`，是 RSS 源反复推的
   机器重复；Supabase 手动收藏的条目 `seen_count` 只有 5-6，信号却强得多。
   SKILL.md 写"seen_count 高的母题加权"，**照做会把 news 的机器重复顶到最上面**。
   → 只在**同一通道内部**比较 seen_count。
2. **索引不跟着库走**。`runs/seen_index.json` 在 gitignore 里，是**机器本地**的。
   260727 实测：本机索引为空，260726 笔记里那些 seen_count 是另一台机器的产物。
   → **换机器后第一轮，所有条目都会显示 seen_count=1（看起来"全是新的"）**。
   这不是热度信号，是索引冷启动。跨周/跨机器的复现判断在索引同步之前不成立。

# 3 关键词设定（矩阵 v3：5 阶段 × 2 行为）

> ⛔ **改词、加词、删词前必读 [[关键词设计推导]]。** 本节只有**结论**（当前跑什么），
> 推导（为什么是这些词、为什么不是 Obsidian / Claude Code / 写作方法 / 搭一套AI系统）在那份文件里。
> 260727 之前推导只存在于对话里、不在文件里，后果是词表不可辩论、不可扩展、不可交接。

## 3.1 矩阵

```
5 阶段 × 2 动机 = 10 格，全部填满

阶段（受众做一条内容时依次卡住的五个时刻）：
  选（不知道发什么）· 写（写不出来）· 改（写出来不能用）· 发（发了没人看）· 攒（素材越攒越乱）
动机（受众和这件事的关系，决定交付物形态）：
  替代（讨厌做，想用 AI 代替我做）· 放大（喜欢做，想用 AI 放大效果）
  「求闻」（发生了什么新事）不进词表 —— 短半衰期，走 news 通道
```

> **第二维 260727 下午从「求解/求证」换成「替代/放大」**：求解求证只影响标题句式，
> 替代放大决定**整条内容的交付物是什么**（同一个「写不出来」，喜欢写的要"怎么写得更好"，
> 讨厌写的要"怎么不用自己写"）。旧的求证列只填了 2/5 格，新维 10 格全满。详见推导 §5.3。

**为什么阶段是这 5 个**：这是一条内容从念头到发布的完整链路，少一环链路就断，多一环就重复。
旧矩阵的 A/B/C/D 四方向是按**创作者的工具箱**切的，回答不了"为什么是这 4 个"，
且 A 方向（出图）260726 零产出——出图是创作者的能力项，不是受众的卡点。详见推导文档 §5。

## 3.2 硬规则

- **句子测试**：候选词必须填得通「我______，怎么办？」。填不通 = 供给侧词，不进表。
- **工具名一律不进词表**（Obsidian / Claude Code / Codex / ComfyUI）。它们的正确落点是
  ① 信号雷达 roster（盯人）② 大盘温度计（测赛道）。理由见推导 §3.3。
- **词里必须含一个「后果」**（没法用 / 写不出来 / 从来不看），不能只有「品类」（写作 / 知识库 / 效率）。
  纯品类词召回的是 SEO 农场文——260726 实测通用 web 域 10 条里 10 条是 AI 写作工具站的推广博客。
- **中文平台用中文词，英文平台（X/Reddit/YouTube）用英文词**——不是翻译，是各自平台上真实的说法
- **词表固化在 §3.4，每次改要留痕**。词一变结果就无法跨周对比，也就无法积累。
- **关键词是召回器不是过滤器**：粗词即可，精筛交给人。穷举必然漏（「用 Codex 写公众号」搜不到「AI 写作」）。
- **每轮跑完做召回体检**（推导 §4）：数提问数/卖货数/赛道外数，决定该词在该域留还是停。
  停用是**按域停用**，不是全局——同一个词在 web 域全是垃圾、在 Reddit 域全是金子。

## 3.3 ⛔ 时效半衰期分层（260726 补，此前完全没有）

**每个词必须标半衰期，时间窗按半衰期取。** 之前一刀切 3-180 天，后果是 GPT5.5 / K3 这种
**发布即过期**的内容照样进库，而费曼学习法 / PARA / 纳瓦尔这类**三年后依然有效**的长尾内容
反而因为窗口太短被切掉。

| 半衰期 | 时间窗 | 说明 | 本赛道的例 |
|---|---|---|---|
| **短（天级）** | ≤ 14 天 | 模型/产品发布。**过期即无价值，宁可不采** | GPT5.6 发布、K3 开源 |
| **中（月级）** | ≤ 180 天 | 具体工具的用法 | Claude Code 教程、Agent 搭建 |
| **长（年级）** | **≤ 1095 天** | **不绑定具体工具的方法/流程/认知**，不过期 | 内容生产流程、一个人做内容、选题方法 |

> **实测（260726 B站首页中位播放）**：Claude Code 89,044 > AI写作 22,633 >
> PARA笔记 13,421 > AI工作流 13,065 > **ComfyUI 3,154**。
> 说明大盘和"追不追新"无关，**跟词本身的受众规模有关**。词表长期偏向短半衰期是结构性错误。

> ⛔ **半衰期是维度，不是选题方向。长半衰期的词同样要过赛道关。**
> 260726 教训：用户用「费曼学习法/PARA/纳瓦尔」举例说明"无时效性内容更值得采"，
> 我**把举例直接当成了方向**，硬编进词表——那些是通用学习法，**不在"自媒体人用 AI 提效"
> 这条赛道上**，采回来也用不了。**举例说明的是原则，不是选题清单。**
