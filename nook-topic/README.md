# nook-topic — 选题判断 skill

发内容没流量，很多时候不是你 AI 用得差，是**选题从第一步就错了**。

选题不是"想"出来的。你熬到凌晨想出来的绝妙创意，平台可能半年前就给别人推过流量了。
单条视频火了是运气，同一个方向三五个不同的人都拍火了，才是真需求。

`nook-topic` 把"翻几百条视频、蹲评论区看大家问什么"这种脏活交给 Agent，
再用一套踩过真坑总结出来的判断规则，把噪声筛掉，给你 3-5 个**值得做**的方向。

**它不采集（采集接外部工具，见下）、不写稿，只做判断这一层。**

## 和别的选题工具有什么不一样

1. **受众关先于热度**。一个话题是真热点，不代表问的人是**你的**受众。这是两件独立的事。
   真实踩坑：某个词的提问数很高（需求极真实），但问的人全是焦虑的普通读者，不是靠内容吃饭的人——
   热度满分，受众零分。所以受众关排在所有判断之前，热度再高也不能免票。

2. **技术控偏置自检**。你手上最新鲜的证据，往往是你刚做完的技术活——这会把选题拽向"讲给同行听"。
   机械判据：这条内容的交付物，一个**不写代码、不装环境、只有手机**的人能不能直接用？不能就砍。

3. **单条爆款 ≠ 规律**。一条内容数据好，只证明这一条成立。要当方法论用，
   必须在多个样本里重复出现，或在你自己的数据里被独立印证过。

4. **关键词设计有推导，不是拍脑袋**。`references/关键词设计推导.md` 回答
   "为什么该搜受众的症状词、不该搜工具名"，给了一个能机械执行的判据
   （能不能填进「我______，怎么办？」），还有完整的召回体检方法——
   怎么判断一个词在某个平台上到底有没有用。**这份文件单独拿去看也有价值。**

5. **低粉爆款优先**。大号火了你拍不一定火（人家有账号权重），
   1 万粉以下的人火了，才说明是**内容本身**在起作用。自带一个零配置脚本干这件事。

## 安装

**方式 A：下载 ZIP**
点绿色 `Code` 按钮 → `Download ZIP` → 解压出 `nook-topic` 文件夹。

**方式 B：git clone**
```bash
git clone https://github.com/captain-nook/nook_skills.git
```

然后把 `nook-topic/` 整个目录放到你的 Agent skill 目录，例如：

| Agent | 目录 |
|---|---|
| Claude Code | `~/.claude/skills/nook-topic` |
| Codex | 放进项目目录即可，会话开始自动读 `AGENTS.md` |
| OpenCode | `~/.config/opencode/skills/nook-topic` |
| Cursor / Windsurf | `<project>/.skills/nook-topic` |

**第一次用之前**：把 `profile.example.md` 复制成 `profile.md` 并填写。
这份档案决定"受众关"怎么判，不填的话 AI 只能用通用判据。

## 采集依赖（四选一，也可以组合）

`nook-topic` 是判断层，它需要有人把样本喂给它。四种方式，从零成本到全自动：

### 选项 1：内置零配置脚本（B站低粉爆款，开箱即用）

不用装任何东西，不用任何 key，`scripts/` 里直接跑：

```bash
python scripts/bili_breakout.py --query "AI写作" --pages 2
```

它做的事：搜 B站 → 查每个 UP 的粉丝数 → 按**播粉比**（播放量 ÷ 粉丝数）筛出低粉爆款。

> ⚠️ **实测提醒**：默认 `--max-followers 10000` 配 `--min-play 50000` 在 B站 比较严，
> 常常筛不出东西——B站 的粉丝量级和小红书不是一个尺度。
> 筛不到时放宽到 `--max-followers 50000`，**播粉比才是真正的判据**，
> 绝对粉丝数只是护栏。实测一条 3 万粉 / 130 万播放（播粉比 42.6x）依然是标准的低粉爆款。

加 `--json` 输出结构化结果，方便喂给 Agent。

### 选项 2：nook-search（推荐，覆盖文字平台）

我们自己的另一个开源 skill，同一个仓库里：**[nook-search](../nook-search/)**

它覆盖 X / Reddit / 知乎 / 微博 / 微信公众号 等文字平台的搜索与清洗，
正好补上 `nook-topic` 最需要的"需求侧信号"（大家在问什么、在吐槽什么）。

安装见 [nook-search/README.md](../nook-search/README.md)。它底层依赖
[AnySearch](https://github.com/anysearch-ai/anysearch-skill)（Apache-2.0，需单独部署，有免费额度）。

### 选项 3：Agent Reach（开源，覆盖需登录的平台）

[Agent Reach](https://github.com/Panniantong/agent-reach) 是一个开源的多平台采集 CLI，
覆盖 `nook-search` 够不到的地方——尤其是需要登录态的国内平台。

```bash
pip install agent-reach
agent-reach install          # 自动装依赖；--safe 只列不装，--dry-run 只预览
agent-reach doctor           # 告诉你哪个通道通、哪个不通、怎么修
```

平台覆盖（据其官方 README，v1.5.0）：

| 平台 | 零配置 | 需配置 |
|---|---|---|
| YouTube | 字幕提取 + 视频搜索 | — |
| B站 | 搜索 + 视频详情（bili-cli，无需登录） | 字幕 |
| Twitter / X | 读单条推文 | 搜索、时间线、长文 |
| Reddit | —（匿名接口已被封） | 搜索 + 读帖和评论 |
| 小红书 | — | 搜索、阅读、**评论** |

> ⚠️ **小红书/抖音这类需登录平台，务必自己评估风控风险。**
> 我们的经验是：用于采集的账号被平台警告过两次，警告针对的是**自动化浏览这个行为本身**，
> 不是请求量——降低频率、加随机延迟都没用。
> 如果你要用，**强烈建议用专用小号，只做读取（搜索/看评论），不做关注点赞发布，小批量低频**。
> 主账号永远不要用于采集登录。

### 选项 4：手动模式（零依赖）

什么都不装也能用。手动复制 5-8 条对标爆款的**标题 + 点赞/收藏数 + 高赞评论**，
直接粘给 Agent，说"用 nook-topic 判断这批素材"。

判断层的价值不依赖采集自动化——自动化只是帮你省时间。

## 怎么用

装好之后，直接对 Agent 说人话：

```text
用 nook-topic，帮我找「AI 写作」方向的选题
```

```text
用 nook-topic 判断一下这批素材值不值得做：<粘贴你采集到的标题和数据>
```

```text
读一下 nook-topic 的关键词设计推导，帮我审一遍这批关键词有没有技术控偏置
```

Agent 会按 `SKILL.md` 的流程走：受众关 → 噪声剔除 → 语义聚类 → 找空隙 → 出 3-5 个候选。

**最后一步它不会替你决定。** 选题单里 `selected` 和 `platform_locked` 两个字段会留空，
等你填。AI 负责把鱼全捞回来并按规则筛，选哪条是人的事。

## 目录结构

```text
nook-topic/
├── AGENTS.md                      # Agent 入口：触发条件、执行顺序、硬规则
├── SKILL.md                       # 主文件：核心认知 10 条、五关判断、输出契约
├── README.md                      # 本文件
├── profile.example.md             # 创作者档案模板（复制成 profile.md 再填）
├── scripts/
│   ├── _common.py                 # 共用小工具（无外部依赖）
│   ├── bili_breakout.py           # B站低粉爆款筛选（零配置，开箱即用）
│   └── youtube_breakout.py        # YouTube 低订阅爆款（需免费 API key）
└── references/
    ├── 关键词设计推导.md            # 关键词第一性原理 + 召回体检方法
    ├── 选题的判断与角度.md          # 五关、差异化角度、证据先行
    ├── 选题单模板.md               # 输出契约：AI 判断四步 + 单子格式
    ├── 采集契约.md                 # 采集层治理：通道穷举、覆盖率报告、通道分权
    └── 采集方法论_v1.md            # 24 维度撒网、锚点×痛点坐标系统、四维预筛
```

## YouTube 脚本的 API key

`youtube_breakout.py` 需要一个免费的 YouTube Data API key：

1. 去 [Google Cloud Console](https://console.cloud.google.com/) 建项目，启用 **YouTube Data API v3**
2. 创建 API 密钥
3. 设环境变量 `YOUTUBE_API_KEY=你的key`，或在 `scripts/` 下建 `.env` 文件写进去

免费额度 10000 units/天，单频道查询约 3 units，日常够用。

**不要把真实 key 提交进任何 git 仓库。**

## 边界

- **不采集**（采集接上面四个选项之一）、**不写稿**、**不出图**。
- `references/采集契约.md` 里出现的 `collect.py` / `weekly_sweep.py` / `opencli` 等命令，
  是原实现里配套编排工具的**示例调用**，本仓库只附带 `scripts/` 下那两个能独立跑的脚本。
  真正可迁移的是**规则本身**：通道穷举、覆盖率报告、通道分权、关键词矩阵。
- AI 不拍板。它给候选和判断依据，最终选择权在你。
