# nook-topic

`nook-topic` 是一个内容选题**判断层** skill。它不采集、不写稿，只做一件事：把一堆采集回来的样本（爆款标题、评论区提问、长文收藏），提炼成 3-5 个"值得做一组内容"的方向。

它假设的场景是自媒体/内容创作者做周期性选题——一个人或一个小团队，要持续从噪声里挑出真正值得做的题，同时不被"信号强但不是我的受众"这种假阳性坑掉。

## 它解决什么问题

选题最容易踩的坑不是"找不到素材"，是**找到了一堆热门信号，但选出来的题不是给你的受众看的**。

`nook-topic` 把这件事拆成三段，缺一不可：

```text
① 脚本采   （你自己的采集工具，任意实现，只要输出结构化样本）
② AI 判    （语义判断：受众关 → 噪声剔除 → 语义聚类 → 找空隙）
③ 人定     （AI 输出 2-3 个候选，最终选择权在人，AI 不拍板）
```

第①段和第③段听起来简单，真正难的是第②段——这是本 skill 的核心价值。

## 核心方法论（这是它和普通"给我出几个选题"prompt 的区别）

- **受众关先于一切**：候选进入判断之前，先问"这条内容的受众是不是我要的那批人"。信号再强，受众不对就砍。这条规则的存在是因为一次真实的踩坑——采集通道全部指向一个母题，五源共识齐刷刷选错方向，因为采的是"同行生态"不是"我的受众"。
- **验证热度 ≠ 验证受众**：一个话题是真实热点，不代表问的人是你的受众。这是两件独立的事，顺序错了会漏判。
- **技术控偏置自检**：你手上最新鲜的证据，往往是你刚做完的技术活——这会把选题往"讲给同行听"的方向拽。机械判据：这条内容的交付物，一个不写代码、不装环境的普通用户能不能直接用？不能就砍。
- **受众动机二分（替代 / 放大）**：受众分两类——讨厌做某件事、想让 AI 代替他做；喜欢做、想让 AI 帮他做得更好。同一个卡点，两类人要的交付物完全相反，出选题时必须先分清打的是哪一类。
- **单条爆款 ≠ 规律**：一条内容数据好，只证明这一条成立。要当方法论用，必须在多个样本里重复出现，或被独立验证过。
- **关键词设计推导**（`references/关键词设计推导.md`）：全 skill 里最耐用的一份方法论。回答"为什么关键词要用受众的症状词，不能用工具名/品类词"，给出一个可机械执行的判据（能不能填进"我______，怎么办？"这个句子），并附完整的召回体检方法（怎么判断一个词在某个平台上到底有没有用）。

## 目录结构

```text
nook-topic/
├── SKILL.md                          # 主入口：触发条件、核心认知、输出契约
└── references/
    ├── 采集契约.md                    # 采集层的治理规则：通道穷举、覆盖率报告、
    │                                  #   通道分权、关键词矩阵（示例命令，非可执行工具）
    ├── 关键词设计推导.md               # 关键词设计的第一性原理 + 召回体检方法
    ├── 选题的判断与角度.md             # 核心判断方法论：五关、差异化角度、证据先行
    └── 选题单模板.md                  # 输出契约：AI 判断四步 + 选题单格式
```

## 这个 skill 不包含什么

- **不含采集脚本**。`采集契约.md` 里出现的命令（`collect.py`、`weekly_sweep.py`、`opencli` 等）是原实现里配套工具的示例调用，本仓库不附带这些脚本——它们绑定具体账号的基础设施（数据库凭据、浏览器自动化环境），因人而异，不适合直接分发。真正可迁移的是规则本身：12 通道穷举、覆盖率报告格式、通道分权逻辑、关键词矩阵设计。换成你自己的采集工具，只要遵守这份契约即可。
- **不含账号人设/确认闸系统**。`SKILL.md` 里提到的"你自己的账号人设文档""你自己的确认闸系统"，是原实现里更上层的编排系统，这里只留了接口位置（哪些字段该由这些系统提供），没有强绑定具体实现。
- **不写稿**。输出是选题方向，不是标题、不是正文。

## 快速开始

对 agent 说：

```text
用 nook-topic，从这批采集样本里给我 3-5 个选题方向。
```

或者先看方法论：

```text
读一下 nook-topic 的 关键词设计推导.md，帮我审一下这批关键词有没有"技术控偏置"。
```

## 适合场景

- 自媒体/内容创作者的周期性选题（周选题会、月度内容规划）。
- 已经有一批采集样本（爆款标题、评论区截图、收藏文章），需要判断哪些值得做。
- 想要一套可复用、可审计的选题判断标准，而不是每次都凭感觉。
- 关键词设计——即使不用整个 skill，`关键词设计推导.md` 单独拿去看也有价值。

## 不适合场景

- 需要开箱即用的采集工具（本仓库不含采集脚本）。
- 只想要"给我 10 个选题"这种一次性输出，不需要判断依据和候选取舍。
- 选题之外的写作、审校、发布环节（这些是独立的 skill）。
